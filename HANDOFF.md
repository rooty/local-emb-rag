## 1. Кто и как работает

- Пользователь: Pipin (GitHub `rooty`), DevOps-инженер и программист (Python, Go).
- Общение только на русском.
- Правила Pipin, обязательные:
  1. отвечать честно; если чего-то не знаешь или не проверил, так и говорить;
  2. перед любыми изменениями сначала рассказать, что хочешь сделать;

## 2. Задача

Консольная утилита + HTTP API на Go, которая отвечает на вопросы пользователей
**только** по локальной базе знаний (md-статьи helpdesk на польском).

- Поиск по эмбеддингам (EmbeddingGemma; модель меняется в конфиге).
- Если в базе ответа нет, отдаётся заранее заданная заготовка «данных нет, пишите/звоните…»
  (`fallback_message`).
- Вопросы ожидаются только на польском. Вопрос на другом языке получает английскую
  заготовку (`language.other_message`).
- Ответ формулирует локальная LLM через Ollama (`gemma4`), строго по найденным статьям.
- Веб-поиска нет (Pipin от него отказался).
- Опционально облако ollama.com с API-ключом.

## 4. Как устроено (кратко)

```
вопрос → проверка языка (слова) → эмбеддинг (query_prefix + вопрос)
       → косинус по всем векторам → группировка по статьям → min_score / max_gap
       → LLM по 1–3 лучшим статьям (+ правило NOT_POLISH, маркер NO_ANSWER)
       → ответ + источники (title, sourceUrl)  |  заготовка + запись в unanswered_log
```

- На каждую статью: фрагменты тела (`chunk_chars` 1200) + каждый вопрос из `questions`
  + строка `keywords`. Для статей Pipin это 6 векторов на статью.
- Причины заготовки (`reason`): `language`, `below_threshold`, `llm_no_answer`.
- Пакеты: `internal/{config,ingest,embed,store,rag,llm,lang,qlog,server}`, `cmd/localrag`.
- Go 1.24, `modernc.org/sqlite` v1.38.2 (без CGO), `gopkg.in/yaml.v3`.
- Проверка: `gofmt -l . && GOTOOLCHAIN=local go vet ./... && GOTOOLCHAIN=local go test -race ./...`

## 5. Что подтверждено на реальных моделях у Pipin

Модели: `embeddinggemma` (EmbeddingGemma **v1** в Ollama, 768 измерений; v2 в Ollama не было)
и `gemma4`. База: 16 польских статей (Chrome, Excel, PowerPoint, Outlook, macOS).

Последний `calibrate` на **новой** версии (после `64c7d9f`):

- правильная статья на 1-м месте у 27 из 29 вопросов;
- правильные вопросы набирают 0.79–0.97, чужие до 0.865 (Wi-Fi на Windows), Word 0.856, Firefox 0.809;
- выбран `min_score: 0.81`; Wi-Fi на Windows и Word выше порога, но LLM их отсекает (`llm_no_answer`), проверено;
- польский вопрос про Chrome даёт польский ответ по шагам статьи, с title и ссылкой.

Промахи поиска (лечатся вопросами в статьях, не кодом):

- «Chrome nie pozwala otworzyć okienka logowania…» → находится `chrome-page-not-loading`, а нужна `chrome-popup-blocked`;
- «Pages zamyka się, gdy otwieram jeden dokument» → `chrome-page-not-loading`, а нужна `macos-app-one-file`;
- «Strona banku otwiera się tylko w oknie prywatnym» → верная статья, но score 0.786 < 0.81.

   что заготовки польская/английская и что пишется `unanswered.jsonl`.

## 8. Грабли — не наступать снова

1. **Пакетные эмбеддинги в Ollama ломаются.** С `embeddinggemma` и `batch_size` > 1 векторы
   мусорные (сходство ≈0.02). По умолчанию `batch_size: 1`; при >1 `index` сам проверяет
   и откатывается. Если «ничего не находится» — первым делом проверить это.
2. **Имя модели — как в `ollama list`.** У Pipin это `embeddinggemma`, а не `embeddinggemma-2`
   (была ошибка 404 model not found).
3. **Старый бинарник.** Однажды целая калибровка шла на бинарнике до `git pull`
   (признак: вывод `источник: файл (0.74)` и русские заголовки в ответе вместо
   `source: <title> (<файл>), 0.74`). После любого обновления кода: `go build`, затем `index`.
4. **Лишние файлы в `docs_dir`.** В индекс попадали старые демо-статьи и подпапка `docs/`;
   `calibrate` сравнивает путь целиком и пишет «мимо» на верные статьи. Перед калибровкой
   проверять `find <docs_dir> -name '*.md'` и вывод `index`.
5. **Не путать `docs/` и документацию.** В клоне Pipin `./docs` — это база знаний
   (`docs_dir` по умолчанию). Документация проекта лежит в `manual/`, не в `docs/`,
   иначе она проиндексируется как статьи.
6. **Вопросы для `calibrate` — перефразы.** Копии `questions` из статей дают завышенные оценки.
   «Чужие» вопросы должны быть действительно без ответа в текущей базе.
7. **Пороги несравнимы.** Между моделями, версиями localrag и наборами статей шкала score
   разная (v1 без front matter: правильные 0.73–0.88; с front matter: 0.79–0.97).
   После любой такой смены — заново `calibrate`.
8. **Смена модели эмбеддингов → перезапуск `serve`, не SIGHUP.** Модель для вопроса
   берётся из конфига при старте; SIGHUP перечитывает только индекс.
9. **Конфиг пользователя перекрывает дефолты.** Новые значения по умолчанию в коде
   не попадут к Pipin, пока он сам не поправит `config.yaml`.
10. **Детектор языка эвристический.** Короткий английский вопрос без служебных слов
    («Chrome blocks a needed popup window») он пропускает; ловит LLM через `NOT_POLISH`.
    В `answer.mode: fragments` этой второй проверки нет.
11. **EmbeddingGemma 2:** FP16 даёт NaN (только BF16/FP32); обязательны префиксы
    `task: search result | query: ` и `title: {title} | text: `.
12. **SQLite-драйвер.** Свежий `modernc.org/sqlite` требует Go 1.26 — зафиксирован v1.38.2 и go 1.24.
13. **GitHub push иногда отвечает 500** на любую ветку. Повторять с паузой (так и прошло);
    на всякий случай сохранять патч (`git format-patch`) в файлы проекта.
14. **Окружение облачной сессии:** huggingface.co был недоступен в старой среде;
    запуск на устройстве Pipin из проекта невозможен (в аккаунте включены trusted devices).
    Модели гоняет только Pipin.
15. **`pkill -f <шаблон>` в shell-сессии** может убить саму команду (exit 144) — искать PID через `ps`.
16. **Не менять ничего без «да» Pipin** — включая статьи в его базе и `examples/docs`.
